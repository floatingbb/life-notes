# 备份与恢复

## 家人日常使用：PDF 与个人 JSON

进入「我们 → 导出格式」。PDF 适合阅读；JSON 格式 2 可以恢复数据。

- PDF 导出当前账号可见的全部未收起记录，包含照片与留言，逐页读取后生成。
- JSON 额外包含本人的回收站，照片和留言图片保存在文件内；不会包含密码、通行码、云端密钥。
- 两种格式都不随首页栏目、当前加载页数或月份筛选缩小范围。
- 恢复时，在「我们 → 恢复 JSON 备份」选择文件，核对数量，点击「确认恢复」。
- 只导入备份原账号自己写的记录；其他人的帖子会跳过。导入到当前登录账号，全部设为仅自己可见；原本收起的仍进入回收站。
- 留言保留原称呼并注明「备份留言」。它不是原家人账号重新发出的留言。原拥抱关系、访问链接和账号权限不会通过个人 JSON 重建。
- 不覆盖现有记录。同一份未改动的文件重复导入会续传未完成部分，不会重复插入已恢复的记录和留言。不同备份文件中的同一则记录仍可能生成不同副本。
- 旧版 JSON 没有原账号标识，不能直接导入。请先在新版网页重新导出；旧文件仍可作为人工查阅资料。
- 导入文件上限 100MB；照片仍为压缩版，不替代原图备份。导出后请确认文件能打开，再妥善保存。

## 管理员灾难恢复：加密整站备份

此工具供维护者在自己的电脑运行，不在普通家人界面开放。它使用维护者自己配置的服务器权限，备份全站持久数据，包括仅自己可见的记录、回收站、成员身份、备注、访问凭据、日记、照片、留言、拥抱以及管理员密码哈希。

内容以 AES-256-GCM 加密，密码经 scrypt 派生密钥。**加密备份和密码分开保管。** 丢失备份密码无法解密。整站备份不是可公开的源码附件，也不要上传 GitHub。

### 创建备份

1. 在项目目录新建仅自己保存的 `.env.private`，按 `.env.example` 配置自己的 CloudBase 环境、地域、网址、服务器 API Key、原实例的 `SESSION_SECRET` 与初始化令牌。不要在聊天、终端命令参数或公开文档填写真实值。
2. 在同一私密文件添加 `BACKUP_PASSWORD=`，自行填写至少 12 位的独立备份密码。程序不会替你读取其他应用的配置或凭据。
3. 等家人暂时停止编辑，运行：

```powershell
node --env-file=.env.private scripts/instance-backup.mjs backup family-backup.ourdays
```

程序读取记录和所有被引用照片，包括回收站；前后两次核对记录，发生变化时会中止，请稍后重试。文件已存在会拒绝覆盖。只有完整获取到记录与引用照片后才写出加密文件。检查文件存在并将其存入自己的安全备份位置。

### 恢复整站

1. 新建**独立、空白**的 CloudBase 环境，先应用数据库迁移并创建私有照片桶；此时不要部署公开云函数或开放网页。
2. 新建目标环境的 `.env.private`。环境 ID、API Key、地域与网址必须属于新环境；先生成临时 `SESSION_SECRET` 和初始化令牌以满足配置校验，填写原备份密码。
3. 在新环境执行：

```powershell
node --env-file=.env.private scripts/instance-backup.mjs restore family-backup.ourdays --new-empty-environment
```

4. 程序拒绝覆盖已有环境；中断后仅允许对同一备份续传，发现目标中有不一致记录会停止。它会先恢复照片、成员和日记，最后写入原管理员账号。
5. 恢复完成后，使用生成的私密 `.env.restore` 中的 `SESSION_SECRET` 配置目标云函数，再按部署说明上线。保留这个原会话密钥是为了让加密保存的家人链接能继续解开。**不要展示或上传 `.env.restore`。** 服务器 API Key 必须使用新环境自己的密钥。
6. 用原管理员密码登录，检查日记、回收站和照片；在访问管理中复制新网址下的成员链接，私下重新发送。新网址不会自动替换家人手机里收藏的旧网址。

整站恢复保留原账号身份、权限、密码哈希和加密访问记录；不会把数据推送到旧环境。恢复工具与网页更新、GitHub 提交之间没有自动部署关系。未在真实家庭数据上执行灾难恢复演练；请先在自己的测试环境使用虚构内容练习。

## 云端照片清理

编辑移除照片时会检查其他记录和留言是否仍在引用，只有不再使用的照片才清理。上传失败、数据库冲突或清理失败会留下可重试的维护记录。

「我们 → 云端照片维护」可检查历史遗留照片；扫描按页进行。24 小时内或无法确认年龄的照片保留，回收站和留言仍在使用的照片也保留。

维护者可在 `our-days-api` 配置名为 `our-days-photo-maintenance` 的 timer，7 段 cron 例如 `0 0 4 * * * *`。每次处理一页并保存扫描位置，后续继续扫描；大量照片会分多次完成。定时调用也计入自己的云资源额度。
